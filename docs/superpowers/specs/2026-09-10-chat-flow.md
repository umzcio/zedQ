# Chat queue and user decisions

Approved in conversation on September 10, 2026. First repair the reported Claude document-generation failure. Then implement the approved queue and user-decision flow.

Queue messages per conversation above the composer. Keep Stop separate from Queue. Send queued items sequentially after successful responses, preserving the preceding response as context. Store text, attachment and note snapshots, selected skills, model and tool choices durably. Provide Edit, Move up/down and Remove through visible and right-click actions. Pause on stop, error, user decision, and restart; restart requires Resume. Navigation must not interrupt a run or move queued messages between chats.

Clarification uses an actual `request_user_input` function call with a concise question, optional suggested answers and free text. Ask only when missing information materially changes the result. The host displays an inline card and resumes the tool loop with the answer. Approval is enforced by the host before execution, with Allow once, Allow for this chat and Deny. A per-chat Ask before tool actions control enables stricter approval; ordinary explicitly requested document work remains automatic by default. Scope remembered permissions to the specific tool in that chat, clear them on restart, and never treat a queued prompt as an answer. Unsupported tool models must remain ordinary chat, with no false claims of structured interaction support.

Use native services for durable state and execution; public module API for IPC; Chat module for UI. Shared Radix menus/dialogs preserve focus and keyboard access. All mutation tests use temporary stores or browser fixtures. Ship a shell capability with the schema/API change. Do not change normal user data for testing.
