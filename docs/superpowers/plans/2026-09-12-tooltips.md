# Consistent app tooltips Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; independent module audits use superpowers:dispatching-parallel-agents.

**Goal:** Explain controls throughout zQ through consistent hover and keyboard-accessible tooltips.
**Architecture:** Shared Radix tooltip primitives live in @zq/ui, with one provider across the shell and persistent modules. Native button/link wrappers retain refs, events and semantics. Module owners supply concise action/state explanations; existing citation preview cards remain their own richer help surface.
**Tech Stack:** React, Radix Tooltip, shared CSS, Playwright browser verification.
**Spec:** User's overnight request to audit the entire app and make almost every control understandable on hover.

## Global Constraints

- Preserve the approved layout, neutral appearance, right-click actions and module boundaries.
- Tooltips contain concise text, not menus or interactive controls. Existing menus stay accessible.
- Use one 450ms pointer delay, 300ms skip window, immediate keyboard focus, Escape dismissal, viewport collision handling and reduced-motion support.
- Keep native disabled semantics; expose the reason through an accessible wrapper when necessary.
- Do not add tooltip behavior to editable document bodies, user chat prose, decorative icons, or existing citation hovercards.
- Test only synthetic data in the isolated worktree/workspace.
