# Chat Flow Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Independent provider debugging and queue work can use the dispatching-parallel-agents workflow.

**Goal:** Repair Claude document creation and implement durable queued messages and user decision pauses.

**Architecture:** Native ChatService owns each run, queue and suspended decision. Modules consume typed IPC and render compact controls. Provider adapters expose the same local tool callback used by document execution.

**Tech Stack:** Electron CommonJS services, TypeScript React modules, shared Radix, Node test runner, isolated Playwright fixtures.

**Spec:** `docs/superpowers/specs/2026-09-10-chat-flow.md`

## Global constraints

- Feature UI stays in modules/chat; native state in apps/desktop/electron.
- Temporary test stores only. No git metadata is present, so no commits/worktrees.
- Preserve old conversations and schema compatibility through optional fields; new module declares new shell capability.
- No model may approve its own action; user decisions arrive only through host IPC.

## Task 2: Durable queue

Files: new `apps/desktop/electron/chat-queue.cjs`, queue schema helper and tests; integration in `chat-service.cjs`, `chat-store.cjs` and `chat-lifecycle.cjs`.

Public interface: `enqueueMessage(sendInput)`, `updateQueuedMessage({conversationId,id,text?,move?:'up'|'down',remove?:boolean})`, `setQueuePaused({conversationId,paused})`, returning ChatSnapshot. Conversation field `queue:{items,paused,error}`; each item has id, text, createdAt, model/connectionId, attachments/context/skill snapshots and tools. Queue admission is atomic with draft removal. Dequeue is atomic with user+assistant insertion so failed preflight retains the item.

- [x] Write failing tests for sequential dispatch, frozen context, edit/reorder/remove, stop/error/restart pause, stale connections, storage failure and duplicate dispatch.
- [x] Implement queue methods in isolated helper; provide exact service integration hooks before changing shared service file.
- [x] Run focused queue/lifecycle tests until green.

## Task 3: User decisions

Files: new `chat-interactions.cjs` and schema/tests, host service run callback wiring, `packages/module-api/chat-types.ts`, preload/main bridge.

Public interface: `respondToInteraction({conversationId,id,answer?,decision?:'once'|'chat'|'deny'})`, `setApprovalMode({conversationId,mode:'auto'|'ask'})`. Message field `interaction` stores id, kind, question, options, status, answer and tool label. Host stores pending resolver separately, validates matching run and rejects stale/double responses.

- [x] Write failing tests for clarification pause/resume, approval before side effects, scoped grants, denial, abort/stale replies and restart.
- [x] Define structured `request_user_input` JSON schema and concise system guidance.
- [x] Wrap local tool execution with host approval; gate selected hosted tools before sending in strict mode.
- [x] Ensure queue waits through decisions and remains paused after denial or cancellation.
- [x] Wire typed IPC with host capability checks and test rejection paths.
