# Code task Kanban and GitHub PR / Issues categories

Code → Tasks → Open PRs tracks selected GitHub.com repositories through the user's existing `gh` login. The repository picker lists up to 500 recently active, non-archived repositories the account can access; owner/name entry covers repositories outside that list. Select all listed repositories, or search and select/clear only matching results while preserving other selections. The native service accepts up to 1,000 repositories. No MCP connection is required.

The board reads open PRs, authors, drafts, review decisions and check summaries, plus open issues, authors, assignees and labels. The default All tracked view includes completed work in Done. Filters also cover open items, authored items, direct PR review requests, issues assigned to the account, repository and search. Team review requests are not included in the direct-request filter. Closed / merged (Closed for issues) contains items previously tracked here, not a full GitHub archive.

Code → Tasks is one Kanban for regular coding tasks, GitHub PRs and issues. Its categories are All tasks, General, Open PRs, Issues, and categories entered on user-created Code tasks. All tasks combines the sources; Open PRs filters the same board. The top-level Tasks module is separate and has no PR integration.

The shared columns are Backlog, To do, In progress, Human Review, and Done. Stored PR workflow names remain compatible with the initial cache (Needs review, Agent reviewing, Needs your input, Ready to merge); the Code UI maps those onto the shared column labels. Dragging and the matching card context-menu actions change only this local stage. A new head invalidates Ready to merge. An agent completing a report moves Agent reviewing to Needs your input; verified merges and closures automatically move to Done, preserving the report and session link. Already-cached closures are repaired on snapshot; reopened items return to To do.

Automatic refresh uses a persisted schedule: five minutes per 50 selected repositories (15 minutes for 130). Reopening the view uses cached data until that schedule is due. Manual refresh remains available outside cooldown, with at most four repository requests in flight. The native service caches results privately in `github/github-board.json`. Failed requests retain cached cards and expose a per-repository warning. Up to 200 open PRs and 200 open issues per repository are fetched; truncation is explicit. An item missing from an open listing is individually checked before being marked closed/merged (up to 20 missing checks per source per refresh). Unverified cards remain stale and cannot start reviews. Removing a repository hides cards without deleting reports. PR and issue refresh errors are independent; either source retains its cache if its own request fails. Issue identities include an issue discriminator and cannot collide with existing PR IDs. Optional issue records extend the version-1 cache without rewriting prior reports.

## Agent reviews

Choose Claude, Codex or Kimi, a native account profile, and a local Code project. Claude/Codex expose their matching account profiles, including custom launchers; Kimi uses its native configuration. The service opens a new native Chat conversation and sends a review request containing the canonical PR URL and head SHA. Prompts explicitly request read-only inspection and a report. These are agent instructions, not an additional tool sandbox: the native harness's own permissions still apply. Agent assignments do not grant GitHub write actions. Explicit user confirmation in Close issue on GitHub uses a separate native close endpoint.

The PR card retains the report and the Code session ID. Open agent uses the public `code.open` command; no sibling-module implementation import is needed. The full conversation remains in the native harness history and can use the existing Code Chat/Terminal flow. Reviews currently run in local Code projects, not SSH projects.

An assignment is durably recorded before startup and before prompt dispatch. An uncertain dispatch is never automatically replayed. Restart reconciliation reads the native session's events and requires a completed-turn event before labelling a report complete. Permission requests, interruptions, startup errors and uncertain launches remain visible. End tracking preserves the native conversation and refuses while the session is busy or awaiting approval; it does not stop the process. Each PR retains up to 50 report rounds. Reports show the last 16,000 characters with a notice when truncated and a link to the full session.

Issue investigations read the current issue and discussion, verify the selected project, attempt safe reproduction using isolated fixtures, then report observed/expected behavior, evidence, suggested fix and verification steps. They stop at Human Review before implementing changes. Feature requests or reproductions requiring unsafe/live mutations must explain the limitation instead. The prompt grants no GitHub write actions; subsequent user instructions remain in the linked native conversation.

End session is available directly on completed/idle agent cards and in the detail/report context menus. It stops the exact linked native session with its current revision, confirms the stop, and closes that workbench tab through the public `code.dismissSession` command. It retains the card, report and native history. Busy/approval/setup states require finishing or stopping the current work in the agent first. Opening a saved session does not dispatch another prompt; its native resume controls remain available. Session status is read from Code on snapshot, including sessions resumed outside the board.

## Release / validation

The shell retains the existing PR cache and adds Code-only task records; it never inserts them into the main Tasks workspace. Board persistence is shell-owned; module rollback does not rewrite it.

- `node --test apps/desktop/tests/github-board.test.cjs apps/desktop/tests/code-codex-protocol.test.cjs`
- `node apps/desktop/tests/github-board.browser.cjs` uses the packaged app, a temporary workspace, a fake GitHub CLI, an isolated Codex configuration and a loopback model endpoint. It does not use a paid model or write to GitHub.
- Opt-in native Claude and Kimi tests also run fresh PR assignments against loopback models through `fixtures/native-pr-review.cjs`.
- `npm run typecheck`, single-module Tasks/Code builds, and the full desktop package.

GitHub commands follow the official [PR CLI](https://cli.github.com/manual/gh_pr_list) and [API CLI](https://cli.github.com/manual/gh_api) contracts.

Code 1.7.6 adds the Issues category, Human Review label, retained Done cards and explicit End session action. It requires `github.issues-lifecycle.v1` and the matching shell release. The same shell update bounds Settings module-version tooltips to their text. Regression coverage includes cached closure repair, PR/issue identity separation, partial sync failures, issue investigation instructions, native stop confirmation, report/native-ID preservation, tab closure, restart, and completed-card visibility in the packaged app.

Code 1.7.7 automatically compacts cards whose linked agent session is stopped. The small card retains repository/number, a two-line title and completion/session status; source icons and workflow color remain. The chevron (keyboard accessible) or context menu expands/collapses the card. Clicking the title opens saved reports, and Open agent remains in the shared menu. Running sessions remain full-size. Expanded ended cards are a temporary view preference; new ended runs and app restart return to the compact default.

Code 1.7.8 distinguishes repositories with Issues disabled from transport/auth failures. Disabled Issues no longer produce connection errors, and prior issue reports are retained as stale until the feature becomes available again. Sync notices occupy one fixed summary row, scoped to the selected GitHub category and repository; Details opens a bounded, scrollable dialog. Genuine errors remain visible and retryable. The issue read is retried on subsequent refreshes so re-enabling Issues recovers automatically. This needs the updated shell and `github.sync-status.v1`. Tests include disabled/re-enabled Issues, auth/rate-limit/transport classification and a packaged board with 20 disabled sources plus two real failures.

Code 1.7.9 adds **Close issue on GitHub…** to issue card menus and details. Its confirmation dialog identifies the repository/issue and offers Completed or Not planned. The native service re-reads the issue, closes that exact issue with an explicit `gh issue close --repo … --reason …`, and verifies closure before moving it to Done. It preserves reports and agent sessions, serializes against sync, and never automatically retries an uncertain write. Already-closed issues are reconciled without another write. Column movement remains local only. Requires the updated shell and `github.issue-close.v1`. Tests use only isolated fake GitHub data.

Code 1.7.10 adds `github.rate-limit.v1`: primary/secondary rate-limit classification, a global persistent cooldown, fail-fast refresh queues (including missing-item verification), and exponential backoff. One rate-status read uses a known exhausted primary bucket’s reset time when available; otherwise backoff starts at one minute. Close and discovery respect cooldown. The board shows the retry time in one summary; the close dialog preserves its selection/error and offers Open on GitHub. No mutation is replayed. The automatic refresh schedule is enforced in the native service across navigation and restart.

Code 1.8.0 adds `github.human-review.v1` and requires this shell update. Human Review cards and their shared menus expose Request changes, Implement suggested fix (issues), and Merge (PRs). Follow-ups reuse the existing native session/account and preserve earlier reports as separate rounds. An ended Chat session resumes with its current revision; busy or Terminal sessions must be handled in the agent first. Dispatch is durable and never automatically replayed. Implementation permits local edits and tests, then returns to Human Review; it does not publish a PR or perform GitHub writes.

Merge previews the latest PR, then revalidates the reviewed SHA, checks, draft status, requested changes, conflicts and branch rules on confirmation. The native REST merge request includes the exact SHA and chosen squash/merge/rebase method. It never uses admin override, deletes branches, or queues automatic merging. Success moves the card to Done; End session remains explicit. An uncertain write is verified once without replay.

Link PR connects an existing GitHub PR to an issue or Code task, with navigation in both directions and a shared Remove link context action. GitHub verifies the selected repository and PR number; links, reports and sessions persist across refresh and restart. This is a local relationship, not an issue-closing GitHub reference.
