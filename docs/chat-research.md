# Chat research runner

Implementation status (2026-09-20): Chat 1.19.0 includes durable research execution, supported provider/source adapters, source and plan review, report artifacts, charts, and exports. It requires the accompanying desktop shell release.

## Ownership and storage

`electron/research/service.cjs` owns execution in the desktop process. No renderer component, subscription, or selected module owns its abort controllers. `store.cjs` keeps one private, versioned JSON checkpoint per job in `<userData>/research`; research checkpoints stay outside ordinary `chat.json`. Chat drafts now include an optional validated Research mode/source selection; selected reference bodies are not added to that draft field. The service is created lazily by the trusted IPC handlers. First access loads saved jobs and marks abandoned running/queued jobs interrupted. It never starts provider requests on recovery.

The API is exported in `@zq/module-api/research-types.ts` and exposed as the optional `DesktopBridge.research`. Host routing reserves `research.v1`. The Chat manifest now declares that capability and must ship with the matching shell. The capabilities `research.v1` and `artifacts.research.v1` cover the Research bridge/catalog, draft persistence, actionable completion notices and report artifact operations; older shell permission sets reject this package. Existing modules and old shells remain compatible because the bridge addition is optional.

The native bridge supports availability, source catalog, create, list/get, plan acceptance, stop, finish, resume, checkpoint-storage retry and summary subscriptions. Its production service supplies `ResearchAdapter` and the real atomic artifact publisher. Research is enabled for supported saved account/model combinations; unsupported models explain their limitation before a job can start.

Inputs include a caller-generated UUID for submission idempotency, conversation/project references, the selected connection/model, the brief, and explicit source selections/scopes. Native resolution pins an adapter ID, connection revision and source revisions/capabilities. The runner compares those bindings before and after every stage, including after resume. The coordinator checks again before each model request or source operation. An adapter cannot broaden the selected scope in its resolved snapshot. Audited connector mappings enforce actual read operations and scopes as described below.

Checkpoints use exclusive temporary files, fsync, rename, then directory fsync. Revision checks prevent stale native owners overwriting a newer checkpoint within the single-instance desktop process. Invalid/corrupt data is preserved and fails closed. Each job is limited to 8 MiB, the store to 128 MiB/200 jobs. Checkpoint failure aborts active I/O and stops scheduling; retry reloads committed disk revisions, checkpoints recoverable state, and requires explicit Resume. No normal workspace or credentials were used in tests.

## State machine and limits

Phase and status are separate. Planning produces an editable plan and `awaiting_plan`. Accepting a current plan with no unresolved questions queues research; collection feeds checking, writing and idempotent publication. A saved report draft precedes publication so a lost publication acknowledgement does not require another writing pass.

There is one active job per conversation and two concurrent native jobs by default. An attempt is checkpointed before dispatch and a validated result before its dependent stage. Stop aborts requests and retains committed evidence. Finish aborts further collection and checks/writes from committed evidence, including an empty evidence set when explicitly requested. Execution generations discard late callbacks after stop/resume. Closing cancels requests and checkpoints interrupted state; reopening never silently starts paid work.

Default budgets are 40 attempts, 30 minutes of active request budget, and 90 seconds per attempt. Collection reserves three attempts/time windows for checking, writing and publication. Retries count; Stop/Resume never resets limits. Each attempt durably reserves its timeout before dispatch. Successful/explicitly stopped requests release unused time. After a crash, the abandoned attempt retains the whole reservation because actual remote consumption is unknown. Token totals contain only reported measurements, with an explicit unmeasured-step count; they are not a cost estimate or a strict token budget.

Events contain only bounded summaries, counts, phase/status and report references. Evidence, findings, plans and attempt details load separately through `get`. Public getters and adapter arguments are detached snapshots. Unknown error diagnostics are sanitized instead of persisting potentially credential-bearing provider responses.

## Native adapter contract

An injected native adapter provides:

- `resolve(input, {signal, material})`: side-effect-free capability/access resolution. Return `{adapterId, connectionRevision, sources}` matching the selected scopes exactly. Resolve the actual saved account/model, available attachments/notes and audited read/search connector tools. Do not acquire credentials in the renderer or issue paid generation here.
- `capture(input)`: copy only the explicitly selected local reference text into native checkpoints. Up to 100 KB per reference/600 KB combined. After a restart, a selected attachment may use that committed copy; removed or changed notes/project files invalidate their binding. Raw material is not included in public summaries/details. Older jobs without a material field remain valid.
- `runPhase({job, signal, stepId})`: one bounded planning/research/check/write attempt. Pass cancellation to all provider/network/tool I/O. Use the selected model; no fallback routing. The saved attempt ID is available for request provenance.
- `publish({job, signal, idempotencyKey, expectedLatestVersionId})`: atomically find or create a report version by its stable publication key. The runner retries with the same key if publication succeeded but its acknowledgement/checkpoint was lost. The production artifact service persists that publication key with its immutable version, including across restart or subsequent edits. Initial publication uses a null expected version. A follow-up uses its selected report version and fails with an actionable conflict if that artifact changed or was deleted during research.

`ResearchAdapter.connection()` checks current conversation/project/model, enabled model, endpoint and ordinary Chat conflicts on every resolution. The runner also supports an optional synchronous `validateContext` hook. Normal Chat checks `researchBusy` before preparation and final dispatch, and its queue skips an active research chat. Resolve/dispatch are native-only; the renderer cannot supply an adapter or executable tool code.

Planning returns `{plan:{title,steps,questions}}`. Research returns `{evidence,findings,gaps,done}`; checking returns `{findings,gaps}`; writing returns `{reportDraft:{title,markdown,citationIds,datasets,charts}}`. Each may include measured `{usage:{inputTokens,outputTokens}}`. A collection result also records bounded native activity (query/read range/connector operation) on its completed step. The draft is checkpointed before the native publisher validates and commits the immutable artifact evidence bundle.

Evidence records distinguish snippets, excerpts and documents, include authorized source IDs, retrieval time, locator and request provenance. Evidence IDs cannot be overwritten with different contents; finding/citation references must resolve. These checks establish structural provenance, not semantic truth. The checking phase asks the selected model to assess claims, conflicts and calculations; exact quotations are additionally checked against saved source text. Live provider quality is not established by deterministic fixture tests; user testing should assess claims and source coverage.

## Research coordinator and sources

The coordinator makes a bounded JSON request for each planning, collection decision, checking and writing stage. One collection decision executes at most one local/connector read or one provider search with up to three native page reads. Model-written prose never becomes evidence. New evidence is committed before a later model request can analyze it. Checking retains collection gaps, including failed/truncated reads, even if the model omits them. Writing must cite existing evidence markers; native code builds the bibliography from saved locators/URLs. No automatic paid response-repair or provider fallback is attempted.

The context budget is 200 KB, with collection stopping before 180 KB so checking/writing have room. This first implementation reads at most 28 KB per page/result; local references support subsequent Unicode-safe offsets. It opens up to three pages per search. Partial coverage remains explicit. Large or unsupported pages never silently become full-document evidence.

Provider requests live in `packages/providers/research.cjs`, independently of ordinary Chat streaming/tool limits. Only supported OpenAI/Anthropic models from the existing hosted-web capability catalog are enabled, at their official endpoints. Other models, including local models, are explicitly unsupported in this first adapter even for local-only research. Native Keychain resolution uses the selected saved account. No renderer credential handling is added.

- **OpenAI:** Responses API with JSON output for coordination; `web_search`, domain filters, search-source metadata and a three-tool-call cap for search. Search citations/URLs are discovery inputs, not evidence text.
- **Anthropic:** Messages API with `web_search_20250305`, `allowed_domains` and `max_uses: 3`. A matched search citation can supply a short, explicitly labeled snippet if the page cannot be read. Encrypted search content is not treated as readable evidence. Tool errors inside HTTP 200 responses are detected. `pause_turn`, refusals and incomplete responses preserve the checkpoint for explicit retry; automatic continuation is not implemented.
- **Web reader:** native public HTTPS text reads, no cookies/authentication, DNS address pinning and public-address checks, scope checks after each redirect, at most three redirects, 1 MiB downloads and 15-second timeout. HTML is parsed as inert text; scripts, styles, navigation and hidden content are excluded. Non-UTF-8, compressed, oversized and binary pages are rejected with a gap. PDFs can instead be selected as attachments with existing extracted text.
- **Local material:** selected notes, conversation/pending attachments and files in the selected project. Unselected project files, project instructions, unrelated conversations and skills are not automatically included. Image-only documents are unavailable for this adapter.
- **Connectors:** only existing bundled arXiv, Gmail, Google Drive and Google Calendar read operations. Exact endpoint/catalog identity, enabled tools, schemas and revision are checked; arbitrary remote MCP servers and mutation tools remain unavailable regardless of `readOnlyHint`. Existing native MCP schema validation, revision checks and cancellation still apply. arXiv returns abstracts/metadata, not full papers.

Connector scope is an explicit list of paper IDs (arXiv), thread IDs (Gmail), file IDs (Drive), or calendar IDs (Calendar). Empty scope means account-wide/public search and read, disclosed in `scopeDescription`. Scoped Gmail/arXiv/Drive selections disable broad search; Calendar requests must stay inside selected calendar IDs. Accepting the plan is the per-job grant for these read operations, not permission to send, edit, upload or delete. The plan UI shows this scope before acceptance. Unrelated connector backlog work remains deferred.

For mixed private-source/Web runs, public search uses only the user-provided brief rather than a model-generated query influenced by private evidence. Web-only runs allow adaptive public queries. The source picker must explain this constraint; richer private-aware query review is a future enhancement. The selected Chat provider still receives selected reference excerpts as needed to perform the research.

API references checked for this implementation: [OpenAI web search](https://developers.openai.com/api/docs/guides/tools-web-search) and [Anthropic web search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool). Reverify before extending model/tool support.

## Chat experience

`useResearch` is mounted by the persistent Chat controller. It subscribes before loading summaries, ignores stale revisions, and fetches detail only for the inspected job. Leaving Chat or selecting another conversation never aborts native work. Active/blocked research is available in the collapsible sidebar section, with identical state-aware actions on chat rows, cards and sidebar entries. Completed cards are compact.

The composer’s Tools menu lists Research and the model’s tools as compact icon/label rows, with a right-aligned checkmark for selected items. Selecting Research changes the trigger to Research and shows Sources; unchecking Research returns to ordinary Chat. Selecting an ordinary tool also returns to Chat. Regular Chat tool selections are preserved when entering Research. There is no separate Chat mode dropdown. Sources is opened from the composer’s Sources control; the Research + menu contains Upload files only. The Sources footer uses the shared dialog action styling. Research asks for a brief and an explicit source selection. The native metadata catalog lists notes, files from the actual chat project, pending/conversation attachments and configured connectors; it never retrieves credentials, calls connectors or sends reference bodies to the renderer. Unsupported sources explain why. Web domains and connector ID scopes are editable, and source rows have context menus. Mixed public/private research explains that Web searches use the brief. Source choices/scopes are saved with the ordinary chat draft and survive reload.

The source picker separates Selected, Web, Files, Notes and Connectors into keyboard-accessible tabs, with category search and 25-item pages. Uploads open the Files tab; ordinary opening starts on Selected. Escape dismisses an open source context menu first, then the picker, including when a tooltip is visible. The composer shows only actionable blocking reasons, without a permanent plan/source instruction.

Planning stops for review. Users can edit the title/steps and answer clarification questions before accepting the current revision. Unsaved plan edits survive switching detail tabs or navigating within the running app; only the accepted plan is durable across restart. Progress displays actual saved activity, evidence/findings, limitations, and usage. Sources distinguish selected versus used and expose saved evidence/citation actions. Stop, Resume, Finish with saved evidence and detail/storage retries call the native service. Normal sending/model changes are blocked in that research chat while other chats remain usable.

Completion uses the generic host notification action to open the report in the originating conversation. It does not navigate or move focus until clicked. The shell owns notification timing/rendering; Chat owns job state and report routing. The report opens in the shared artifact pane and remains available in the artifact library.

## Validation

Run `node --test apps/desktop/tests/research-*.test.cjs`, `node apps/desktop/tests/research-ui.browser.cjs`, and `npm run typecheck`. The browser harness uses the actual native Chat/Research services and temporary checkpoints with a simulated model/publisher; it never opens the regular workspace.

The research suites cover durable phase transitions, generation races, non-cooperative cancellation, scoped bindings, plan revisions, bounded queuing, collection/timeout limits, crash recovery, publication acknowledgement loss, corrupt/unsafe storage, disk failures and retry, safe errors, detached snapshots, and bridge subscription cleanup. New adapter tests cover conflicting-source fixtures, unsupported-claim removal, persistent selected attachments, provider payloads/errors, exact quotations/citations, selected-only reads, DNS/redirect/size limits, connector scope/schema enforcement and account revocation between requests. Providers, network results and publication are deterministic fakes in disposable temporary directories. These tests establish mechanics, not live model quality.

Milestone 2 validation: 62 research tests and 191 existing Chat/provider/MCP/shell regression tests passed. Milestone 3 validation: 124 combined research/Chat/queue/close/module regression tests, native-backed browser flow, typecheck and signed single-module API compatibility passed. Browser coverage includes source-scope editing/Escape, context menus, draft reload, plan edits/clarifications/tab persistence, detail retry, keyboard tabs, navigation to Code, independent ordinary Chat, Stop/Resume/Finish, and completion/report routing without focus theft. Source/plan layouts were inspected in light and dark themes. The signed package was built with an ephemeral test key, verified for the target shell and rejected by an older capability set, then removed. No live paid model calls, external mutations, installation or regular-workspace changes were performed. `npm audit` still reports four entries in the existing ExcelJS/uuid and PptxGenJS/image-size dependency chains (two moderate, two high); neither new reader dependency (`htmlparser2`, `ipaddr.js`) appears in the report. No unrelated dependency downgrades or automatic audit fixes were applied.

## Report artifacts and exports

A report version stores Markdown, citation IDs, immutable source evidence, findings, limitations, the accepted plan, source scopes, chosen model and optional typed datasets/chart specifications. Artifact blobs use existing hash verification and atomic index persistence. The native publication key prevents duplicates if the app restarts between artifact commit and research checkpoint acknowledgement. Deleted artifacts retain prior versions; a follow-up cannot overwrite a newer edit.

Reports support Edit report (new immutable version), Follow up with research (new plan/run against the selected version), source-evidence inspection, and chart View data. Report actions are shared between pane and library. Chart, dataset and source context menus expose the corresponding inspection/copy/export actions. Follow-ups reuse explicit sources and add up to 32 KB of the previous report to model context; private prior text never enters adaptive Web queries.

Charts are deterministic bar, line or scatter plots from saved typed datasets, limited to eight datasets/charts, 200 rows and eight columns (40 categories for bars). Units and per-row citation IDs are preserved. Numeric data must be transcribed from numbers present in cited evidence; this is a provenance guard, not proof that the model chose the correct number or unit. Derived chart transformations are deferred; calculations may appear in prose with their method. Missing values remain missing and line gaps remain disconnected.

Exports: Markdown ZIP with report.md, sources.json, SVG figures and CSV datasets; PDF with the same data and vector charts; individual SVG and CSV downloads. Exported source metadata excludes the copied private evidence excerpts. The in-app report keeps those excerpts for inspection. CSV strings are protected against formula interpretation. Reports render inert Markdown and native chart geometry; arbitrary HTML/scripts and model-supplied SVG are not executed.

Validation uses disposable native and browser workspaces with a deterministic provider. It covers publication/restart idempotency, immutable edits/follow-ups, stale conflicts, unsafe/missing chart data, PDF/ZIP/data parity, navigation during research, stop/resume/finish, keyboard focus, and light/dark report rendering. Live paid-provider report quality remains for user evaluation.

Release verification: 326 native/regression tests passed (five optional environment-dependent tests skipped), typecheck passed, native-backed browser coverage passed, and the signed Chat 1.19.0 package passed matching-shell verification and older-shell capability rejection. The packaged Electron app passed isolated Research navigation/report/export checks and its PTY detach/replay runtime check. Light/dark reports and the exported PDF were visually inspected. No live provider generation or mutation of the normal workspace was used for testing.
