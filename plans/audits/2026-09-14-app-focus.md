# App audit and recommended focus — 2026-09-14

Source baseline: `f696c75`. Scope: existing HQ, Notes, Tasks, Chat loading/reading paths, workspace and local-file persistence, native export paths, module boot/recovery, CI and dependency checks. All connector work remains deferred. This is a hotspot-weighted source audit with focused isolated checks, not an exhaustive UI/accessibility audit or performance certification.

Recommendation: repair the existing daily workflows and save failure paths before starting another large subsystem. Then develop user-owned projects for Notes/Tasks. The loading z is the only implementation authorized and made during this audit; other findings below remain open.

### 1. Task command visibility

Both `tasks.new` and `tasks.edit` set editor state, while the dialog additionally requires the active view to be Tasks. Confirmed in an isolated packaged app: the Notes linked-task action showed no dialog; switching to Tasks revealed the pending editor. Existing focused tests do not exercise this cross-module UI path.

Fix direction: make public task commands consistently navigate and open, or deliberately support an editor outside the Tasks surface. Preserve selection text and note identity. Verify Notes, HQ, and search entry points, cancellation, focus return, and no duplicate creation. Do not redesign the board to fix this.

### 2. Workspace input limits and recovery

Native limits include 4,096 UTF-8 bytes for titles and 2 MiB for note bodies, task descriptions, and quick capture. Editors accept input without enforcing those limits. Since autosave sends the complete workspace, one invalid field blocks the complete snapshot. In-memory validation probes confirmed invalid state rejection before filesystem writes; this is not evidence of existing user data loss.

Fix direction: share limits through the public module API; validate UI edits and command payloads; retain over-limit input as a recoverable draft with a specific explanation. Do not silently truncate pasted content. Cover multibyte text, aggregate limits, and continued saving of valid changes. This needs a coordinated shell/module change.

### 3. Export durability

Native export handlers use direct `writeFileSync` on the chosen destination. An isolated evaluation of the actual `artifacts:save` handler with an injected partial disk-full failure replaced an existing fixture file with three bytes before rejecting. Native editor saves already use atomic replacement; extend that guarantee to exports.

Fix direction: centralize private sibling-temporary writes, complete/fsync them, then atomically replace the approved destination. Preserve overwrite confirmation and cleanup behavior. Fault-injection tests must prove existing files survive failed writes. No real user files were used.

### 4. Module boot isolation

Per-module recovery correctly attempts previous/bundled candidates. However, when one module exhausts those candidates, `loadModules` rejects globally and `main.tsx` never mounts `DesktopRoot`. An in-memory compiled-loader probe confirmed subsequent healthy modules were not attempted. This differs from the already isolated render-error path.

Fix direction: continue loading healthy modules and retain a failed-module contribution with repair guidance. Settings must remain reachable. Test aggregate startup, missing command owners, and repair navigation. Do not weaken signature or API compatibility checks.

### 5. HQ activity semantics

HQ selects `notes[0]` and `notes.slice(0,4)`, while note edits update array entries in place. The note model stores a display string for `updated`; edits set it to the literal `Just now`.

Fix direction: explicitly distinguish last opened from last edited, persist real activity data, and derive relative time labels when displaying them. Verify create A/create B/edit or open A/restart. Preserve independently controlled sidebar and tab ordering.

## Follow-up investigations and verification gaps

- **Save work scales with total stored data.** `apps/desktop/src/App.tsx:34` forwards every workspace change; `DesktopRoot.tsx:32` serializes all snapshots without coalescing. `storage.cjs:60` validates, rereads, and synchronously rewrites the store. Local file edits similarly queue every revision (`modules/notes/file-controller.ts:53`), and close flush rewrites every retained document (`:79`). High confidence in repeated work; latency has not been benchmarked. M effort, medium fix risk: measure isolated large fixtures before changing scheduling, then coalesce obsolete pending snapshots while preserving explicit Save/close/conflict semantics.
- **Rare Voice startup hang.** `apps/desktop/electron/voice-service.cjs:10` opens settings without `O_NONBLOCK` before checking file type. An isolated FIFO fixture hung a child process until timeout. S effort, low risk: match existing bounded regular-file readers and add a regression. Low practical frequency; not the next product focus.
- **UI coverage misses important workflows.** Default `npm test` runs desktop `*.test.cjs`; root `test:ui` runs tooltip coverage. CI separately runs document-font coverage but not the shared artifact security/view suites, general browser suites, or a full application build. See `.github/workflows/checks.yml`, root `package.json`, and `packages/ui/package.json`. Add relevant integration cases alongside each fix rather than treating passing helper tests as whole-app proof.

## Product direction — separate from defects

1. **User-owned Notes/Tasks projects (recommended next feature; L).** `packages/module-api/data.ts:6` still hardcodes `zQ`, `llm-img`, and `zBrain`; Notes and Tasks use these choices directly. Build stable project identities and real creation/rename/settings/icon/delete behavior, including consistent context menus. Decide the relationship to Chat projects before migration; identical names alone are not shared identities. This gives existing Notes/Tasks a meaningful daily workflow without adding another runtime.
2. **Cross-Mac continuity and tested data backup (L; design first).** The spec calls for shared data with local recovery and conflict preservation (`docs/zq-product-spec-v0.1.md:117`, `:170`, `:183`), while README explicitly states cross-Mac sync is not implemented. A GitHub source backup is not an application-data backup. Select the always-on host, backup destination, and conflict policy before implementing synchronization; keep local file contents out unless explicitly selected.
3. **Memory with explicit capture first (L; product choice).** The memory scope in `docs/zq-product-spec-v0.1.md:254` distinguishes source archives, extracted memory, provenance, and correction/deletion. Start with reviewed “remember this” capture and cited recall if selected. Automatic capture/promotion remains undecided. Work is still a reserved module (`modules/work/README.md`); Code remains deliberately deferred. Neither should be labeled broken or started as an audit fix.

## Considered and rejected

- “Notes and Tasks need a redesign”: unsupported; specific workflow defects and fixed project choices justify targeted work instead.
- “Replace all atomic JSON stores”: the storage choice is intentional; fix measured scheduling and input-boundary problems before proposing a migration.
- “Missing Memory/Work/Code means broken features”: these are documented future scopes, not regressions.
- “Every npm audit high entry requires an immediate package change”: reachability matters; the suggested `pptxgenjs` downgrade is not a verified remediation for this app.
- More connector work: explicitly deferred by the user.
