# Voice implementation and research — 2026-09-09

## Engine decision

On-device uses Apple's `SFSpeechRecognizer` with `SFSpeechURLRecognitionRequest` on a temporary PCM WAV file. The helper compiles for the app's macOS 13 minimum using the installed SDK, with no third-party model download, executable dependency, or provider fallback. Language support is discovered from the runtime. A successful compile does not establish that a particular Mac has usable speech assets for a given language.

Apple states that `requiresOnDeviceRecognition` only takes effect when `supportsOnDeviceRecognition` is true. Both conditions are therefore enforced immediately before recognition; the service also checks support before asking to record. A missing language, denied permission, helper failure, or recognition error stops local transcription. It cannot route audio to OpenAI. Sources: [Apple on-device support](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition), [on-device request requirement](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition), [file recognition request](https://developer.apple.com/documentation/speech/sfspeechurlrecognitionrequest).

Provider mode supports saved OpenAI connections using the standard `https://api.openai.com/v1` endpoint. Custom endpoints and other connection types are excluded. The bounded model choices are `gpt-4o-mini-transcribe`, `gpt-4o-transcribe`, and `whisper-1`; these have the single-language-hint file transcription interface. The current guide recommends a newer `gpt-transcribe` interface with different language/context options, so it is not silently substituted into this implementation. Input is WAV multipart at `/audio/transcriptions`, with JSON output and an optional language hint. [Official OpenAI file transcription documentation](https://developers.openai.com/api/docs/guides/speech-to-text), [GPT-4o Mini Transcribe](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe).

The current official pricing table estimates $0.003/minute for `gpt-4o-mini-transcribe` and $0.006/minute for `gpt-4o-transcribe`. Actual availability and billing depend on the saved account and may change. No provider request or paid test was made. Local transcription incurs no OpenAI API usage. [Official OpenAI pricing](https://developers.openai.com/api/docs/pricing).

## Recording, permissions, and packaging

The reusable recorder begins a native reservation before requesting `getUserMedia({audio, video:false})`. AudioWorklet collects mono samples; the renderer retains them only for the current recording. Device IDs use exact matching so a missing selected microphone produces an error instead of recording another input. Device labels may be hidden until the user grants microphone permission.

Recording is limited to 60 seconds. Reaching the limit stops capture and waits for explicit **Stop & transcribe**; it never uploads automatically. Stop closes capture before submitting bounded WAV bytes. Cancel closes tracks, clears samples, cancels native processing and suppresses delayed results, including a permission dialog or transcription that completes after cancellation. Explicit record/stop/cancel controls, elapsed time, errors, and a non-animated status work with the keyboard and reduced-motion preferences.

The native service owns a single reservation and snapshots mode, language, device, model, and connection metadata at Begin. Settings changes affect only new recordings. Native credentials are resolved through the existing Keychain service when provider work actually starts; they are never exposed to the renderer. Connection changes or removal may cause an explicit failure, never substitution.

Electron permission request and check predicates require the exact trusted webContents, main frame URL, main-frame flag, active recording reservation, and audio-only media type. A common `file:` origin is insufficient. Camera, screen capture, subframes, other windows, unknown media types, and permission checks outside an explicit recording are rejected. Both handlers are necessary per [Electron Session documentation](https://www.electronjs.org/docs/latest/api/session) and [MediaAccessPermissionRequest](https://www.electronjs.org/docs/latest/api/structures/media-access-permission-request).

The app includes `NSMicrophoneUsageDescription` and `NSSpeechRecognitionUsageDescription`. The Swift helper embeds its own speech usage string in its Mach-O Info.plist, links the system Speech framework, and is signed as nested runtime code. It requests speech authorization only for explicit local transcription, not Settings inspection. [Apple speech authorization](https://developer.apple.com/documentation/speech/asking-permission-to-use-speech-recognition), [microphone usage description](https://developer.apple.com/documentation/bundleresources/information-property-list/nsmicrophoneusagedescription), [speech usage description](https://developer.apple.com/documentation/bundleresources/information-property-list/nsspeechrecognitionusagedescription).

`scripts/build-voice.mjs` builds/caches arm64 or x64 macOS 13 binaries. The current package targets arm64. Release signing should use a stable `ZQ_VOICE_SIGN_IDENTITY`; the development default is ad-hoc signing. Actual macOS TCC attribution to the app/helper and successful recognition still require an attended packaged microphone/speech test. These were deliberately not exercised unattended.

## Retention and verification

Voice settings live in a separate native `voice.json`, leaving Appearance and normal workspace state unchanged. Settings reads have an O_NOFOLLOW check and 16 KB limit; writes use exclusive temporary files, fsync and atomic rename. Explicitly saving after corruption preserves a recovery copy. Local audio files are owner-readable/writable only and removed after success, failure, cancellation completion, or on next startup after a crash. Provider audio stays in memory. This is application-level deletion, not a claim of secure physical erasure or control over a provider's retention.

Provider responses are streamed with a 256 KB byte limit. Transcripts are valid UTF-8 without NUL, limited to 64 KB. The shared controller captures the originating chat and delivery callback. The Chat integration must retain that controller in persistent module state and append delivered text to the original chat's editable draft without submitting a message. Settings uses the same recorder and a separate editable test field with Copy/Clear actions via visible controls and context menu.

Verified with fixture-only native service, permission, and renderer controller tests: immutable settings; cancellation before/during upload; delayed microphone permission cleanup; duplicate Stop; 60-second capture limit without upload; Stop waiting for audio finalization; origin delivery; local failure without fallback; temp cleanup; saved-connection exclusion; invalid WAV; symlink defense; corrupt-settings recovery; bounded provider response; invalid/overlong transcripts. `node scripts/build-voice.mjs`, codesign verification, and the desktop TypeScript check passed. No actual microphone, speech authorization prompt, real credential access, or paid API use was performed. Packaged UI and main/preload integration verification remain part of the parent release run.
